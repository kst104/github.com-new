# 월간 수익 되먹임 · 계절성 상품 알고리즘 가이드

매달 번 돈의 절반을 다시 광고로 돌려 다음 달 유입을 키우고, 그 달에 가장 잘 팔리는 계절 상품 하나씩을 골라 붙이는 운영 규칙입니다. 계산은 `engine/revenue_feedback.py`가 하고, 이 문서는 그 계산을 승태 님이 눈으로 확인하고 직접 조정할 수 있게 풀어 쓴 설명서입니다.

| 구분 | 내용 |
| --- | --- |
| 정산 주기 | 매월 말 집계, 매월 1일 확정 |
| 되먹임 비율 | 수익의 50% (매달 협의로 변경 가능) |
| 예산 나누는 곳 | 검색광고(파워링크) + 콘텐츠 부스팅(쇼츠·릴스) |
| 상품 구조 | 쿠팡파트너스 1종(일반형 블로그) + 네이버 쇼핑 커넥트 1종(전문가형 칼럼) |
| 코드 | `engine/revenue_feedback.py` |
| 상품 카탈로그 | `engine/data/seasonal_products.json` |
| 정산 입력 예시 | `engine/data/settlements/2026-11_sample.json` |
| 리포트 출력 | `reports/revenue_feedback/<YYYY-MM>_settlement.json` · `_report.md` |
| 노션 보드 | 허브 아래 「📈 월간 수익·되먹임 정산 보드」 |

## 1. 한 장 구조

```
[매월 말]  유입 · 클릭 · 수익 · 광고비 집계
        ↓
[정산]    총수익 × 되먹임 50%  →  다음 달 광고 예산
        ↓            (최소 집행 단위·월 상한·시드 예산 안전선 통과)
[배분]    검색광고 ↔ 콘텐츠 부스팅   (직전 ROAS가 높은 쪽에 무게)
        ↓
[상품]    다음 달 계절에 맞는 대표 상품 1+1 선정 (계절 적합도·수요·수익성·데이터 신뢰)
        ↓
[집행]    다음 달 광고 집행, 매주 중간 점검
        ↓
[다음 정산] 결과를 다시 넣어 반복
```

이 구조의 핵심은 두 가지입니다. 첫째, 광고비를 감(感)이 아니라 지난달 숫자에서 뽑습니다. 둘째, 잘 된 채널에 다음 달 돈이 더 붙고 못 된 채널은 최소선까지만 남습니다.

## 2. 입력은 다섯 가지뿐

| 입력 | 어디서 보나 |
| --- | --- |
| 블로그 조회수·방문자 수 | 네이버 블로그 통계 |
| 쇼츠 조회수 | 유튜브 스튜디오 분석 |
| 제휴 클릭수(쿠팡 / 쇼핑 커넥트) | 쿠팡파트너스 리포트, 쇼핑 커넥트 리포트 |
| 플랫폼별 수익 | 같은 리포트의 발생 수익 |
| 그달 집행한 광고비 | 네이버 검색광고, 메타·유튜브 광고 관리자 |

이 다섯 개를 `engine/data/settlements/<YYYY-MM>.json`에 적고 아래 명령을 돌리면 끝입니다.

```bash
cd work/content-automation-engine
python3 engine/revenue_feedback.py settle --input engine/data/settlements/2026-12.json
```

파일 없이 구조만 확인하고 싶을 때는 내장 샘플로 돌립니다.

```bash
python3 engine/revenue_feedback.py simulate --month 2026-11
python3 engine/revenue_feedback.py score --month 2026-12      # 상품 순위만
python3 -m unittest engine.test_revenue_feedback -v           # 계산 검증 27건
```

## 3. 계산식

### 3-1. 다음 달 광고 예산

```
되먹임 예산 = 그달 총수익 × 되먹임 비율(0.5)
```

여기에 세 가지 안전선을 순서대로 겁니다.

| 순서 | 규칙 | 이유 |
| --- | --- | --- |
| 1 | 계산된 예산이 3만 원 미만이면, 프로그램 1~3개월 차에는 시드 5만 원 | 3만 원 아래로는 파워링크 지면이 제대로 잡히지 않음 |
| 2 | 3개월이 지나면 강제 집행하지 않고 계산된 금액만 배정 | 손실을 키우지 않기 |
| 3 | 아무리 커도 월 30만 원 상한 | 초기에 매출보다 광고가 커지는 것 방지 |

### 3-2. 효율 지표

| 지표 | 식 | 보는 법 |
| --- | --- | --- |
| ROAS | 수익 ÷ 광고비 | 1.0 넘으면 광고비보다 수익이 큼 |
| 유입당 수익(EPV) | 수익 ÷ (블로그 방문자 + 쇼츠 조회수) | 유입 1회의 값 |
| 유입당 광고비(CAC 대용) | 광고비 ÷ 총유입 | 유입 1회를 사 오는 값 |
| 클릭당 수익(EPC) | 수익 ÷ 제휴 클릭 | 링크 1클릭의 값 |
| 광고 의존도 | 광고비 ÷ 수익 | 수익 중 광고로 만든 몫 |

### 3-3. 채널 배분

1. 광고를 아직 한 번도 안 돌린 달은 기본값 **검색 60 : 부스팅 40**으로 시작합니다.
2. 이력이 쌓이면 채널별 ROAS를 계산합니다. 집행액이 적은 채널의 ROAS가 우연히 튀는 것을 막으려고 사전 집행액 5만 원만큼을 평균 ROAS 쪽으로 당겨 스무딩합니다.
3. 스무딩한 ROAS가 높은 쪽에 예산을 더 줍니다.
4. 한 채널이 30% 아래로, 다른 채널이 70% 위로 가지 않게 자릅니다.
5. 직전 ROAS가 1.0 미만인 채널은 30%까지만 줍니다.

예산은 1,000원 단위로 떨어지고, 두 채널 합은 항상 총예산과 정확히 같습니다.

## 4. 계절성 대표 상품 선정

### 4-1. 계절 구분

| 시즌 | 개월 | 테마 |
| --- | --- | --- |
| 겨울 | 11·12·1·2월 | 한파·난방·호흡기/보습 |
| 봄 | 3·4·5월 | 환절기·알레르기/미세먼지 |
| 여름 | 6·7·8월 | 냉방·제습·수분/자외선 |
| 가을 | 9·10월 | 환절기·면역/관절 |

### 4-2. 점수

```
종합 점수 = 0.36 × 계절 적합도
          + 0.27 × 수요(검색량 65% + 리뷰수 35%, 로그 정규화)
          + 0.27 × 수익성(건당 수수료 60% + 단가대 25% + 평점 15%)
          + 0.10 × 데이터 신뢰(플랫폼에서 직접 확인 1.0, 추정 0)
```

- 계절 적합도: 해당 시즌 주력 1.0, 앞뒤 시즌 0.5, 비시즌 0.15
- 단가대: 5,000원 미만은 수수료가 너무 작고, 4만 5천 원까지가 가장 전환이 잘 되는 구간, 15만 원을 넘으면 급격히 떨어짐
- 데이터 신뢰: 확인된 값 1.0, 추정치 0. 이 가중치가 있어서 검증되지 않은 추정 후보가 실제로 확인한 상품을 밀어내지 못합니다. 추정 데이터로 상품을 갈아치우면 한 달 매출이 통째로 흔들리기 때문입니다.

### 4-3. 교체 규칙

"별도 코멘트 전까지 같은 플랫폼 안에서는 같은 제품" 원칙을 코드로 옮겼습니다.

- 현재 상품이 이번 달에도 1순위면 **유지**
- 1순위가 다른 상품이어도 점수 차가 0.08 미만이면 **유지**
- 0.08 이상 앞서면 **교체 제안** (승태 님 확인 후 반영)

교체는 자동으로 되지 않습니다. 리포트에 "교체 제안"으로만 뜨고, 승태 님이 확인하셔야 다음 달 카탈로그의 `current_products`가 바뀝니다.

### 4-4. 카탈로그 갱신

`engine/data/seasonal_products.json`에 후보를 추가하거나 수치를 고칩니다.

```json
{
  "name": "상품명",
  "platform": "coupang",
  "price": 17800,
  "commission_rate": 0.03,
  "monthly_search_volume": 120000,
  "review_count": 81001,
  "rating": 4.5,
  "seasons": ["winter", "spring"],
  "tags": ["호흡기", "한파"],
  "verified": true,
  "source": "쿠팡파트너스 상품 검색 2026-11-20"
}
```

`verified`는 플랫폼 화면에서 직접 본 값일 때만 `true`로 둡니다. 나머지는 `false`로 두고 매달 실제 수치로 바꿔 주세요.

## 5. 2026년 11월 초기 정산 결과 (시뮬레이션)

11월은 유기 트래픽만으로 시작한 달이라 광고비가 0원입니다. 실제 값이 아니라 구조 검증용 샘플로 돌린 결과입니다.

| 항목 | 값 |
| --- | --- |
| 블로그 2,830회 / 방문자 1,240명 | 쇼츠 3,150회 |
| 쿠팡 클릭 96 · 수익 8,544원 | 쇼핑 커넥트 클릭 12 · 수익 23,256원 |
| 총수익 | 31,800원 |
| 되먹임 50% | 15,900원 (1,000원 단위 16,000원) |
| 안전선 적용 | 최소 집행 단위 미달 → 시드 50,000원 |
| 12월 배분 | 검색 30,000원 + 부스팅 20,000원 |
| 12월 대표 상품 | 쿠팡 한스웰 KF94 마스크 유지 · 네이버 들꽃잠 배 찜질팩 유지 |

읽는 법: 첫 달 수익 3만 원대에서는 50%를 떼도 1만 6천 원이라 광고 지면이 안 잡힙니다. 그래서 1~3개월 차에만 5만 원 시드를 쓰고, 그동안 ROAS 데이터를 모아 4개월 차부터 수익 기반으로 넘어갑니다. 시드 구간에서는 광고비가 수익보다 18,200원 많습니다. 이건 손실이 아니라 다음 달 유입을 사는 초기 투자이고, 3개월 뒤 ROAS 1.0을 넘겼는지로 회수 여부를 판단합니다.

### 12월 2회차 검증 (배분이 실제로 움직이는지)

12월에 검색 3만·부스팅 2만을 집행하고 수익이 108,920원까지 올랐다고 가정한 시나리오입니다.

| 항목 | 값 |
| --- | --- |
| 총수익 / 광고비 | 108,920원 / 50,000원 |
| ROAS | 2.18 (검색 2.00 · 부스팅 2.45) |
| 1월 예산 | 54,000원 |
| 1월 배분 | 검색 26,000원 + 부스팅 28,000원 (48 : 52) |

부스팅 ROAS가 더 높아 예산이 부스팅 쪽으로 4,000원 넘어갔습니다. 이게 되먹임이 작동하는 모습입니다. 매달 이 계산이 반복되면 잘 되는 채널이 스스로 커집니다.

## 6. 매월 1일 정산 루틴 (10분)

1. **숫자 모으기 (5분)**: 네이버 블로그 통계, 유튜브 스튜디오, 쿠팡파트너스·쇼핑 커넥트 리포트, 광고 관리자에서 지난달 숫자를 뽑습니다.
2. **정산 파일 채우기 (2분)**: `engine/data/settlements/<지난달>.json`에 옮겨 적습니다. `program_month`는 시작한 달을 1로 세어 적습니다.
3. **실행 (1분)**: `python3 engine/revenue_feedback.py settle --input <파일>` → 리포트 두 개(JSON·Markdown)가 나옵니다.
4. **확인 (2분)**: 리포트 7번 "승태 님 확인이 필요한 항목"만 보시면 됩니다. 되먹임 비율, 시드 승인, 상품 교체 여부 세 가지입니다.
5. **노션 기록**: 정산 보드에 그달 행을 추가하고 예산·상품·메모를 남깁니다.

매주 월요일에는 예산의 절반 이상이 이미 소진된 채널이 있는지만 봅니다. 그런 채널은 증액하지 않고 남은 기간 동안 유지합니다.

## 7. 광고 집행 안전선

| 안전선 | 값 | 이유 |
| --- | --- | --- |
| 되먹임 비율 | 50% | 번 돈의 절반만 광고로, 절반은 현금으로 |
| 월 상한 | 300,000원 | 잘 돼도 초기에 과감하게 키우지 않음 |
| 최소 집행 단위 | 30,000원 | 이보다 작으면 지면이 안 잡혀 의미 없음 |
| 채널 최소 비중 | 30% | 한 채널 몰빵 금지 |
| 채널 최대 비중 | 70% | 반대쪽도 남겨 둠 |
| ROAS 하한 | 1.0 | 못 넘긴 채널은 최소 비중까지만 |
| 시드 기간 | 1~3개월 차 | 이후엔 수익 기반으로만 |

이 중 어느 하나라도 바꾸고 싶으시면 `Guardrails` 값만 고치면 됩니다. 숫자를 바꾸면 리포트와 노션 보드에 그대로 반영됩니다.

## 8. 알아 두실 점

- **수익 귀속은 가정값입니다.** 검색 글에서 결제가 일어나고 쇼츠는 발견·재방문에 기여한다는 전제로 검색 70 : 부스팅 30으로 나눕니다. 정산 파일의 `attribution`을 고치면 바뀝니다. 2~3개월 데이터가 쌓이면 실제 전환 경로를 보고 조정하는 게 좋습니다.
- **상품 카탈로그의 '추정' 값은 추정입니다.** 마스크와 배 찜질팩 두 개만 플랫폼에서 확인한 값이고, 나머지는 후보 비교용 추정치입니다. 매달 실제 검색량·리뷰수로 갱신해 주세요.
- **교체는 자동이 아닙니다.** 리포트가 제안하고, 승태 님이 확인하시면 다음 달에 반영됩니다.
- **수익이 0원인 달**에는 예산이 0원으로 나옵니다. 시드 기간이 지난 뒤에는 억지로 광고를 돌리지 않고 유기 확장을 우선합니다.
